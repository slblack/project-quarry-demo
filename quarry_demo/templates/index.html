How the guard works

Project Quarry is Cisco's open-source rule engine for agent conversations. Rules read messages, tool calls, tool results and the order they happen in. Each rule compiles to a small state machine before any traffic arrives.

Customer messageOptional AI Defense prompt inspection in live mode
Tool call, before it runsBlocked: the tool never executes
Tool result, before the model reads itQuarantined: the model sees a notice instead
Agent reply, before the customer sees itWithheld: a safe message is shown

What makes it different

  • Order matters. A after B matches only when B happened first. An address change followed by a refund is blocked; a refund followed by an address change is not.
  • Values can be carried between steps. The exfiltration rule captures the email address from the profile it read, so emailing the customer is allowed and emailing anyone else is not.
  • Pending calls are visible. A tool call with no result yet (call.response == null) is the moment to block it.
  • Models only when needed. In the AI-judge rule, cheap local checks decide whether to ask the model at all. Ordinary lookups never reach it.
  • Evidence for every decision. Each block shows the conversation steps that triggered it, any captured value and any model score against its threshold.
  • Fails closed. If a scan cannot finish (a timeout or a judge error), the guard blocks rather than guessing.

How this demo decides

The guard keeps the conversation as Quarry should see it. Before each step takes effect it scans the conversation plus that step. If a rule matches that did not match before, and the rule is enforced at this point, the step is stopped. Blocked calls and quarantined content never enter the conversation, so the same rule fires again if the agent retries.

Honest limits

  • Quarry is in alpha (v0.1). Rule syntax may change before v1.0.
  • This alpha cannot compare a numeric tool argument in a step, so the £150 and 30% limits are written as patterns over the raw arguments.
  • In scripted mode the AI judge is an offline keyword stand-in so replays are repeatable. In live mode it is the OpenAI model you choose in Setup.
  • All data, people, cards, addresses and web pages are fictional. No email is sent and no money moves.

Quarry project: github.com/cisco-ai-defense/project-quarry (Apache 2.0).
